## Introduction

Terraform provider for managing a context. A context is a set of key-value pairs that can be used to enable or
disable a module, as well as generating consistent resource names and tags for cloud resources.

This provider is intended to be a replacement for Cloud Posse's
[terraform-null-label](https://github.com/cloudposse/terraform-null-label) Terraform module as well as the
[context.tf](https://github.com/cloudposse/terraform-null-label/blob/main/exports/context.tf) export from that module,
which is copied into all of Cloud Posse's modules and components (root modules) via automation.

The provider is designed to be more flexible and easier to use than the `terraform-null-label` module, and to provide
a consistent way to manage context across all of Cloud Posse's modules and components via a provider, rather than a
Terraform module. This provider also allows flexibility in the property names that can be used to generate labels and
tags, where the previous module-based solution was limited to a fixed set of properties (namespace, tenant, stage,
environment, name and attributes).

### Data Sources

The provider includes three data sources:

- **`context_label`** — Generates a label string from context values. Supports two modes:
  - **Delimited**: Joins property values with a delimiter (e.g. `acme-core-prod-uw2-example`)
  - **Templated**: Uses a Go template string (e.g. `{{.namespace}}/{{.tenant}}/{{.stage}}/{{.name}}`)
- **`context_tags`** — Generates a map of tags from context values, with configurable case transformations for keys and values.
- **`context_config`** — Reads the current provider configuration, useful for passing context to child modules.




## Usage

Here is how to use this provider in your own Terraform code:

```hcl
terraform {
  required_providers {
    context = {
      source  = "cloudposse/context"
      version = ">= 0.4.0"
    }
  }
}

provider "context" {
  delimiter = "-"
  enabled   = true

  properties = {
    namespace   = { required = true }
    tenant      = {}
    stage       = {}
    environment = {}
    name        = { required = true }
  }

  property_order = ["namespace", "tenant", "stage", "environment", "name"]

  tags_key_case   = "title"
  tags_value_case = "none"

  values = {
    namespace   = "acme"
    tenant      = "core"
    stage       = "prod"
    environment = "uw2"
    name        = "example"
  }
}

# Generate a delimited label: "acme-core-prod-uw2-example"
data "context_label" "delimited" {
}

# Generate a templated label: "acme/core/prod/example"
data "context_label" "templated" {
  template = "{{.namespace}}/{{.tenant}}/{{.stage}}/{{.name}}"
}

# Generate tags from context values
data "context_tags" "this" {
}

# Read the provider configuration
data "context_config" "this" {
}
```

### Using with Atmos

The context provider is designed to work with [Atmos](https://atmos.tools) for managing provider configuration
across environments. Atmos generates a `providers_override.tf.json` file that configures the provider automatically.

See the complete [demo-context](https://github.com/cloudposse/atmos/tree/main/examples/demo-context) example for a
full working setup.

**Define provider properties and defaults in your stack configuration:**

```yaml
# stacks/deploy/_defaults.yaml
terraform:
  providers:
    context:
      enabled: true
      delimiter: "-"
      property_order:
        - product
        - region
        - environment
        - name
        - instance
      properties:
        product:
          required: true
        region:
          required: true
          validation_regex: "^(east|west)$"
        environment:
          required: true
          max_length: 7
        name:
          required: true
        instance: {}
      tags_key_case: title
      values:
        product: "acme"
        component: "{{.atmos_component}}"
        stack: "{{.atmos_stack}}"
```

**Override values per environment:**

```yaml
# stacks/deploy/dev/myapp.yaml
import:
  - ../_defaults
  - catalog/myapp

terraform:
  providers:
    context:
      values:
        environment: dev
```

**In your component, declare an empty provider block** — Atmos fills in the configuration:

```hcl
# components/terraform/mycomponent/providers.tf
provider "context" {}
```

**Use context values for Atmos stack naming:**

```yaml
# atmos.yaml
stacks:
  name_template: "{{.providers.context.values.product}}-{{.providers.context.values.region}}-{{.providers.context.values.environment}}"
```

See the [Docs](./docs) for additional information.
